# V0.9 — Architecture & Validation Freeze

## Purpose

V0.9 is a stabilization milestone, not a feature milestone. No new product feature is accepted unless it is required to complete architecture, validation, release reproducibility, or repository governance.

## Canonical baseline

- Canonical V0.9 input baseline: `cbfb4c24db99b86bee1a2f2c8ac603a095f08914`
- Historical pre-V0.8.4 checkpoint: `888a15df9a8206b922e53edc8a4ba457d462c93c`
- Freeze branch: `dev-v0.9-architecture-validation-freeze`

`888a15d` remains an important engineering checkpoint, but it is not the final V0.9 baseline because V0.8.4 was merged after it and revalidated.

## V0.9 exit criteria

V0.9 can be promoted only when all five gates pass:

1. **Repository governance freeze**
   - PR #5 archived without merge.
   - `main` is no longer allowed to remain behind the validated production line at V1.0 promotion.
   - New work uses short-lived branches and PRs.

2. **Architecture freeze**
   - Version-chained GUI modules (`dynamic_gui_v07x/v08x`, `gui_release_v07x/v08x`) are removed from the runtime dependency graph.
   - One canonical dynamic GUI module and one canonical release GUI module remain.
   - Compatibility behavior is verified by regression tests before legacy modules are deleted.

3. **Golden regression freeze**
   - Real production/engineering DAT files are stored outside source code if licensing/confidentiality requires it, but every Golden case has a manifest entry with SHA-256, source/customer profile, expected outputs, tolerances, and sign convention.
   - Golden tests must fail on result drift outside tolerance.
   - Synthetic fixtures may test edge cases but may not substitute for real DAT Golden cases.

4. **Release reproducibility freeze**
   - A version tag triggers tests, Windows EXE build, SHA-256 generation, and GitHub Release publication.
   - Release artifacts contain the executable and checksum file.
   - Release provenance records tag, commit SHA, Python version, and workflow run.

5. **V1.0 readiness**
   - Algorithm behavior is frozen.
   - Golden outputs are frozen.
   - Runtime architecture is frozen.
   - EXE is reproducible from a clean runner.
   - Every delivered executable is traceable to one tag and one commit.

## Engineering invariants retained from V0.8.4

- Rebound force is positive; compression force is negative.
- Response timing reference and current/force endpoint rules remain unchanged during V0.9 unless a Golden regression proves a defect.
- Target velocity remains independent from BMW/Audi profile selection.
- Gas rebound-force correction behavior remains unchanged.

## Change policy during V0.9

Allowed: refactor with behavior-preserving tests, regression infrastructure, release automation, repository cleanup, documentation needed for traceability.

Not allowed: feature expansion, algorithm tuning without evidence, UI redesign unrelated to architecture consolidation, silent tolerance changes.
